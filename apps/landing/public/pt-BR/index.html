A daily do seu time, escrita no seu agente de IA.

O Standcast é uma ferramenta de código aberto para a daily de times de software. Rode /daily no Claude Code, no Cursor ou no terminal. O Standcast rascunha o seu ontem a partir da sua atividade no GitHub e no Linear, você confirma e o seu time recebe um consolidado no Slack ou no Google Chat.

Um dia com o Standcast

Defina dois horários no standcast.yml. O Standcast cuida do resto.

Este time tem remind_at: "09:30" e digest_at: "10:00" no horário de São Paulo, de segunda a sexta.

  1. 08:50 · rascunho

    Ana roda /daily

    Ela edita o rascunho, adiciona um impedimento com link para um pull request e confirma. Quem revisa recebe uma mensagem direta.

  2. 09:30 · remind_at

    Davi recebe um lembrete

    Ele ainda não escreveu. Nunca mais de um lembrete por dia.

  3. 10:00 · digest_at

    O consolidado chega

    Um por time no #daily-backend: primeiro os impedimentos, depois as atualizações, depois quem não enviou.

  4. 10:40 · atrasada

    Davi envia atrasado

    A daily dele vai para a thread do consolidado, e ninguém perde nada.

Veja como funciona

O que ele faz

Coleta, consolida e entrega. Você só escreve.

Um rascunho do trabalho real

Pull requests abertos, mergeados e revisados, commits por repositório e cards do Linear que começaram ou terminaram. Na segunda, o rascunho cobre o fim de semana.

Impedimentos chegam a quem pode ajudar

Um impedimento com link para um pull request vai para os reviewers, depois para o CODEOWNERS, depois para os gestores do time. Um card do Linear vai para o responsável pelo card que está bloqueando.

Nada sai sem você

A tool de envio do MCP exige confirmed: true, que o agente só passa depois que você aprova o texto.

Vários times, uma daily

Escreva uma vez e apareça no consolidado de todos os seus times, cada um no próprio fuso horário e nos próprios dias úteis.

Gestores leem pelo próprio agente

Consolidados, dailies e impedimentos dos últimos 90 dias, pelas tools de leitura do MCP. Só conteúdo confirmado.

API e webhooks

API keys somente leitura com escopos, uma referência OpenAPI e webhooks assinados daily.submitted e blocker.opened.

Integrações

O GitHub faz o rascunho. O chat recebe o consolidado.

Um tracker acrescenta os seus cards. Cada time escolhe o próprio chat, e o Linear é opcional.

  • rascunho

    GitHub

    Pull requests, reviews e commits no rascunho. Uma organização instala o Standcast como GitHub App.

  • tracker opcional

    Linear

    Os seus cards aparecem no rascunho, e um impedimento de card vai para quem é dono do card que bloqueia.

  • chat

    Slack

    Um consolidado por time, dailies atrasadas na thread, um lembrete e mensagens diretas.

  • chat

    Google Chat

    O mesmo consolidado num espaço, pelo app do Standcast.

Privacidade

Feito para times, não para vigiar pessoas.

O Standcast sugere impedimentos a partir dos seus próprios sinais. Essas sugestões são suas. Um teste na CI garante que elas nunca saem do seu rascunho.

Entenda a privacidade

  • Sem métricas de produtividade
  • Sem rankings
  • Sem contagem de commits
  • Nada enviado em nome de ninguém

Configuração como código

Um arquivo no seu repositório .github.

Times, horários, canais de chat e gestores ficam no standcast.yml. Toda mudança passa por review, como código.

  • Validado a cada push. Um check run Standcast config aponta a linha com erro.
  • Nunca quebra o time. Um push inválido mantém a última configuração válida em vigor.
  • Times do GitHub. Os membros podem ser logins ou @org/team.

Referência do standcast.yml

.github/standcast.yml

teams:
  - name: Backend
    timezone: America/Sao_Paulo
    workdays: [mon, tue, wed, thu, fri]
    remind_at: "09:30"
    digest_at: "10:00"
    chat:
      provider: slack
      channel: "#daily-backend"
    tracker:
      provider: linear
      team: BE
    managers: [bruno]
    members: ["@acme/backend"]

Perguntas frequentes

Antes de instalar.

Outra dúvida? Escreva para support@standcast.app ou leia a documentação.

O Standcast lê o nosso código?

Não. O GitHub App lê pull requests, reviews, checks, metadados de commits, o standcast.yml e o CODEOWNERS. Ele nunca lê arquivos de código.

O meu gestor vê os impedimentos sugeridos para mim?

Não. As sugestões aparecem só para você, no seu rascunho. Elas nunca chegam ao consolidado, à API, aos webhooks nem aos gestores.

O Standcast pode enviar uma daily por mim?

Não. A tool de envio do MCP exige confirmed: true, que o agente só passa depois que você aprova o texto.

Do que eu preciso?

Uma organização ou conta pessoal no GitHub, e um workspace no Slack ou o Google Chat do Google Workspace. O Linear é opcional.

Dá para hospedar por conta própria?

Sim. O Standcast tem licença MIT. A seção de self-hosting do README cobre a API, o worker e o Postgres.
