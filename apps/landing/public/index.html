A day with Standcast

Set two times in standcast.yml. Standcast runs the rest.

This team has remind_at: "09:30" and digest_at: "10:00" in São Paulo time, Monday to Friday.

  1. 08:50 · draft

    Ana runs /daily

    She edits the draft, adds a blocker that links a pull request and confirms. The reviewer gets a direct message.

  2. 09:30 · remind_at

    Davi gets one reminder

    He hasn't written yet. Never more than one reminder a day.

  3. 10:00 · digest_at

    The digest arrives

    One per team in #daily-backend: blockers first, then updates, then who hasn't sent.

  4. 10:40 · late

    Davi sends late

    His daily goes in the digest thread, so nobody misses it.

What it does

Collects, consolidates and delivers. You only write.

A draft from real work

Pull requests opened, merged and reviewed, commits by repository, and Linear cards that started or finished. Monday covers the weekend.

Blockers reach who can help

A blocker that links a pull request goes to its reviewers, then CODEOWNERS, then the team managers. A Linear card goes to the owner of the blocking card.

Nothing sent without you

The MCP submit tool needs confirmed: true, which the agent passes only after you approve the text.

Several teams, one daily

Write once and appear in every team digest you belong to, each in its own time zone and workdays.

Managers read from their agent

Team digests, dailies and blockers for the last 90 days, through MCP read tools. Confirmed content only.

API and webhooks

Read-only API keys with scopes, an OpenAPI reference, and signed daily.submitted and blocker.opened webhooks.

Integrations

GitHub builds the draft. Your chat gets the digest.

A tracker adds your cards. Each team picks its own chat, and Linear is optional.

  • draft

    GitHub

    Pull requests, reviews and commits in the draft. An organization installs Standcast as a GitHub App.

  • optional tracker

    Linear

    Your cards show in the draft, and a card blocker goes to the people who own the blocking card.

  • chat

    Slack

    One digest per team, late dailies in the thread, one reminder and direct messages.

  • chat

    Google Chat

    The same digest in a space, through the Standcast app.

Privacy

Built for teams, not for watching people.

Standcast suggests blockers from your own signals. Those suggestions belong to you. A test in CI checks that they never leave your draft.

Read how privacy works

  • No productivity metrics
  • No rankings
  • No commit counts
  • Nothing sent on anyone's behalf

Configuration as code

One file in your .github repository.

Teams, times, chat channels and managers live in standcast.yml. Every change is reviewed like code.

  • Checked on every push. A Standcast config check run points to the line with the error.
  • Never breaks the team. An invalid push keeps the last valid config in effect.
  • Teams from GitHub. Members can be logins or @org/team.

standcast.yml reference

.github/standcast.yml

teams:
  - name: Backend
    timezone: America/Sao_Paulo
    workdays: [mon, tue, wed, thu, fri]
    remind_at: "09:30"
    digest_at: "10:00"
    chat:
      provider: slack
      channel: "#daily-backend"
    tracker:
      provider: linear
      team: BE
    managers: [bruno]
    members: ["@acme/backend"]

FAQ

Before you install.

Another question? Write to support@standcast.app or read the documentation.

Does Standcast read our code?

No. The GitHub App reads pull requests, reviews, checks, commit metadata, standcast.yml and CODEOWNERS. It never reads source files.

Can my manager see my suggested blockers?

No. Suggestions are visible only to you, in your own draft. They never reach the digest, the API, webhooks or managers.

Can Standcast send a daily for me?

No. The MCP submit tool needs confirmed: true, which the agent passes only after you approve the text.

What do I need?

A GitHub organization or personal account, and a Slack workspace or Google Chat in Google Workspace. Linear is optional.

Can we self-host?

Yes. Standcast is MIT licensed. The self-hosting section of the README covers the API, the worker and Postgres.
